# NPC 동시 이동 부하 테스트

## 실행

```bash
npm run dev
# 브라우저: /tools/npc-stress.html?count=100
```

휴대폰에서는 개발 서버에 접속할 수 있는 공유 URL에서 같은 경로를 연다. 휴대폰의 `localhost`는 클라우드 개발 서버가 아니다. 상단에서 0·25·50·100명을 선택하고 35초 동안 화면을 계속 켜 둔다. 같은 기기·브라우저·화면 방향에서 반복 비교한다.

CDP를 제공하는 Chrome이 이미 실행 중이면 자동 측정할 수 있다. 스크립트는 자기 테스트 탭만 닫으며, 일반 게임 코드는 변경하지 않는다.

```bash
CDP_URL=http://127.0.0.1:9222 \
NPC_STRESS_URL=http://127.0.0.1:5173/tools/npc-stress.html \
NPC_STRESS_OUTPUT=/tmp/npc-stress-results \
node tools/npc-stress-browser.mjs
```

## 포함한 부하

- 실제 `Npc` 클래스, 로웬 마을 배경·건물·소품과 `WalkArea` 장애물 검사를 사용한다.
- 현재 게임에 연결된 리네아·시아·루안의 8방향 걷기 텍스처를 공유해 복제한다. 100종의 다른 텍스처를 로딩하는 실험은 아니다.
- 각 NPC의 이름표·그림자·방향·애니메이션·깊이 정렬·이동 목표 선택을 처리한다.
- 테스트에서만 대기 시간을 생략하고 플레이어를 멀리 둬 대부분의 NPC가 계속 움직이게 한다. 실제 이동 코드와 속도는 그대로다.
- 모든 NPC의 발 위치가 카메라 안에 있는지 자동 검사한다. 이동 중인 평균 인원도 결과에 기록한다.
- 주인공·전투·공격 이펙트·적 AI·NPC 간 충돌/회피·게임 UI는 포함하지 않는다.

## 측정 해석

1280×720 게임 캔버스, 854×480 CSS 뷰포트, DPR 2 조건이다. DPR 설정이 게임 내부 해상도를 2배 올리지는 않는다. 5초 준비 후 실제 30초의 프레임 간격을 측정한다. FPS는 프레임 수/측정 시간, P95는 프레임 간격의 95백분위 값이다. NPC 갱신 시간에는 그리기와 GPU 실행 시간이 포함되지 않는다.

CPU 4배 제한은 클라우드 CPU 속도를 제한하는 비교 조건이며 특정 휴대폰을 재현하지 않는다. SwiftShader 결과로 모바일 GPU 성능을 판단할 수 없다. 일반 실행 0명과 100명, CPU 제한 0명과 100명을 각각 비교해야 한다.

텍스처 메모리는 텍스처 관리자에 등록된 이미지의 `너비×높이×4` 합계다. 텍스트·렌더 타깃·밉맵·드라이버 복사본 등을 모두 포함한 실제 GPU 메모리가 아니다. JS heap 역시 이미지 디코딩 및 GPU 메모리를 포함하지 않는다. WebP 파일 용량과 디코딩 메모리는 별개다.

엔진 전환 판단에는 실제 목표 안드로이드 기기에서 동일 테스트를 반복하고, 별도로 전투 부하와 장시간 발열을 확인해야 한다.

## 클라우드 측정 결과 (2026-11-15, 한국 시간)

측정 당시 코드 기준은 `00cf754`입니다. 이후 합쳐진 NPC 전원 이동·전투 연출 변경을 포함한 재측정 결과가 아니며, 아래 수치는 당시 기록으로 보존합니다. 도구 자체는 현재 NPC 클래스를 불러오므로 재실행하면 최신 코드로 측정합니다.

Chrome 156 / SwiftShader 소프트웨어 렌더링. 각 조건 1회 측정이므로 수치는 기기 성능 보증이나 반복 측정 평균이 아니다.

| NPC 수 | CPU 제한 | 평균 FPS | 프레임 간격 P95 | NPC 갱신 평균 | 평균 이동 인원 |
|---:|---|---:|---:|---:|---:|
| 0 | 없음 | 16.4 | 77.5ms | 0.01ms | 0.0 |
| 25 | 없음 | 14.1 | 81.5ms | 0.17ms | 23.8 |
| 50 | 없음 | 11.9 | 109.5ms | 0.29ms | 47.7 |
| 100 | 없음 | 9.7 | 123.7ms | 0.41ms | 95.7 |
| 0 | 4배 느리게 | 14.0 | 83.7ms | 0.02ms | 0.0 |
| 100 | 4배 느리게 | 7.9 | 170.6ms | 1.47ms | 96.1 |

100명 조건에서 화면 안 발 위치의 최소 인원은 100명이었다. 나무·건물에 가려지는 인물도 있다. 등록 텍스처의 기본 픽셀 메모리 추정치는 34.3MiB, JS heap 관측치는 51.8MiB였다. 서로 다른 100종의 이미지 메모리는 검증하지 않았다.

일반 조건은 0명에서도 16.4 FPS, 100명에서 9.7 FPS로 이 클라우드 환경에서는 부드럽지 않았다. NPC 이동 갱신은 약 0.41ms지만 프레임 전체 간격은 평균 약 103ms다. 따라서 이번 결과만으로 NPC AI가 주된 병목이거나, 실제 모바일에서도 같은 FPS가 나온다고 결론 내릴 수 없다. GPU가 없는 환경의 그리기 부하와 나머지 프레임 처리를 분리해 해석해야 한다.

100개의 NPC 인스턴스가 움직이고 프레임이 바뀌는 기능은 확인했다. 모바일 30/60 FPS 달성 가능 여부와 Unity 전환 필요성은 아직 판정하지 않았다. 다음 검증은 실제 목표 휴대폰에서 같은 장면을 측정하고, 이후 전투 부하를 추가하는 것이다.
