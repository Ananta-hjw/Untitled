# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

`AGENTS.md` holds the repository's style, testing and commit conventions; follow it. This file adds what you need to work safely in the code.

## Working with the user

- Never commit or push on your own. Always ask the user first, every time. `.claude/settings.json` enforces this with a PreToolUse hook (`.claude/hooks/confirm-git-commit-push.sh`) that forces a permission prompt for `git commit`, `git push` and GitHub MCP file writes.
- The user writes in Korean; reply in Korean. Code comments and README are mostly Korean too.

## Commands

```bash
npm ci                     # install
npm run dev                # Vite on :5173, reachable from a phone on the same network
npm run typecheck          # tsc, strict, no emit (there is no linter)
npm test                   # node --test tools/*.test.mjs — needs Node.js 24+
npm run test:browser       # real game in headless Chromium; set CHROMIUM_PATH if `chromium` is not on PATH
npm run build              # dist/
npm run build:single       # dist-single/index.html with all JS and images inlined
npm run android:apk        # build + cap sync + gradle assembleDebug (needs the Android SDK)
```

Run one test file, or one test by name:

```bash
node --test tools/blade.test.mjs
```

```bash
node --test --test-name-pattern='회피' tools/*.test.mjs
```

The Node tests import `.ts` sources directly through Node 24's type stripping. Modules they import (`config.ts`, `entities/heroFrames.ts`, `entities/movement.ts`, `entities/progression.ts`, `entities/saveData.ts`, `story/dialogues.ts`, `world/interactables.ts`, `combat/blade.ts`, `combat/justDodge.ts`, `ui/settingsData.ts`, `world/navGrid.ts`) must stay free of Phaser and of Vite-only imports such as `?inline`, or the tests stop loading. Put new pure logic in modules like these so it can be tested. A pure module that imports another one must spell the `.ts` extension (`'../config.ts'`) for Node; `allowImportingTsExtensions` in `tsconfig.json` lets TypeScript accept it.

`?debug` in the URL draws the walkable polygon and obstacles. In dev builds the `Phaser.Game` is exposed as `window.__game`, which the browser test and ad-hoc Playwright checks use.

## Architecture

**One scene, one clock.** `scenes/GameScene.ts` runs a whole session. All gameplay timing uses the scene's own `now` (ms), advanced in `update()` by `min(delta, 50)`. Attack timing, combos, dodge, invulnerability, respawns and effects all compare against it. Do not use `this.time.delayedCall` or `Date.now()` for gameplay; they drift from the game clock when frames drop. Per-run state is reset in `resetState()` from `init()`, because class field initialisers run only once and the scene must survive `scene.restart()`.

**Frame-rate independent motion.** Lunges and dodges are not speed × dt. They move by the change in an integrated progress curve (`entities/movement.ts`), so the distance is identical at any frame rate. Tests assert this at 20/30/60/120 fps. Keep new displacements in that form.

**Characters.** `entities/Character.ts` is a container whose position is the feet and whose depth is its y (y-sorting). Its body is either a Phaser `Sprite` (the slimes, from code-drawn textures in `world/placeholderArt.ts`) or a `HeroSprite` (the player). Both are driven by animation keys named `${key}-idle`, `${key}-walk`, `${key}-attack1..3` and `${key}-dodge`.

**The hero.** `entities/HeroSprite.ts` shows whole-character frames from `src/assets/hero/academy/*.png`. `entities/heroFrames.ts` is the pure part: it picks one of 8 facings from actual displacement (with hysteresis), maps attacks to the 6 non-vertical attack facings, and decides which frame is shown at each ms of an action. Frame rectangles plus foot and blade anchors live in `frames.json`, generated by `tools/build_hero_frames.py` (`ANCHORS`, `DIAGONAL_ATTACK_ANCHORS`). The source sheets are never edited.

**Hits come from the drawn blade.** `HeroSprite.getBlade()` returns the guard and tip in world space for the current frame. `GameScene.updateAttackTrace` sweeps the blade between frames and tests it against each enemy with `combat/blade.ts` (`bladeHitsEllipse`, `clipBladeSweep`), inside a ground-plane lane from `insideAttackLane`. The trail effect uses the same blade positions, so what you see is what hits. Three timings must agree: each combo stage's `hitDelayMs`/`intervalMs` in `config.ts`, the pose start times in `heroFrames.ts` (`POSE_STARTS`, `ACTION_DURATION`), and the drawn strike frame. `tools/hero-sprite.test.mjs` checks that.

**World.** `world/village.ts` builds the starting village with a separate ground texture, protagonist home and nature props. `villageLayout.ts` holds spawn points and ground footprints; village art and measured frames live in `src/assets/village/`. `WalkArea` uses rectangular building walls and ellipse obstacles for trunks/rocks, and divides movement into short steps to prevent dodge tunnelling. Draw depth follows the ground contact Y. `world/navGrid.ts` is one shared flow field toward the player; it is recomputed only when the player changes cell, and enemies use it only when the straight line is blocked.

**Enemies.** `combat/Enemy.ts` is a small state machine: wander → chase → windup (telegraph) → strike → recover, timed on the game clock. When the strike lands it records `lastStrikeAt` and calls back into the scene, which decides whether the player is hit (`strikeReaches` in `combat/justDodge.ts`).

**Just dodge.** A dodge started within `JUST_DODGE.windowMs` before a strike lands, from a spot the strike would have reached, is a just dodge (`isJustDodge`, checked against the dodge's start position, once per dodge). It slows the game clock: `update()` multiplies the frame step by `slowMotionScale(...)` for `slowMs` of real time, so enemies, the player and all game timers slow together. It also resets the dodge cooldown, stuns the dodged enemy for `stunMs`, and marks the next attack started within `counterMs` as a counter (`attackTrace.counter`, damage × `counterDamage`).

**No per-hit allocation.** Damage numbers (`ui/DamageNumbers.ts`, digits drawn once to a texture), blade trails and dodge ghosts (`combat/CombatEffects.ts`) reuse pooled objects. Keep new combat effects pooled; the target is low-end Android.

**Progression.** The scene keeps `progress` (level, xp) and `stats` (max HP and damage for that level) and resets both in `resetState()`. Killing an enemy calls `gainXp()`, which uses the pure `entities/progression.ts` (`addXp`, `statsForLevel`, `xpToNext`); a level-up raises max HP, heals fully, and updates the name label, the HUD XP bar and the pooled effects in `ui/ProgressEffects.ts`. Player damage reads `stats`, not `PLAYER.damageMin/Max` directly. Progress survives death and is saved to `localStorage` (key `untitled-rpg.save`, versioned) on every XP change by `entities/saveData.ts`; `init()` loads it, so restarts and app relaunches continue from it. The storage is passed in, so a blocked or full `localStorage` only disables saving, and a corrupt or out-of-range save is ignored (new game). Bump `SAVE_VERSION` when the saved shape changes. Uninstalling the app clears the save.

**Dialogue.** `world/interactables.ts` lists talkable spots (ground position, reach radius, marker height, dialogue id); `story/dialogues.ts` holds the lines (speaker, text, optional portrait), currently placeholder text until the story is written. When the player stands near a spot and no enemy is chasing or attacking, the scene shows a marker and a 대화 button (keys E/Enter). `ui/DialogueBox.ts` types lines out and advances on any tap, E/Enter or Space/J. While it is open `update()` returns before advancing `now`, so the whole game is frozen; on close the scene clears buffered attack and dodge input so the advancing key does not attack. Portraits are runtime copies (e.g. `assets/hero/dialogue/neutral-768.png`); add new ones to `PORTRAITS` in `DialogueBox.ts` and the `Portrait` type. New NPCs need an interactable entry, a dialogue entry and their own sprite.

**Pause and settings.** The top-right II button, Esc, the Android back button (`@capacitor/app` `backButton` listener; without it Android would close the app) and the game going hidden all open `ui/PauseMenu.ts`. While it is open `update()` returns before anything else, so the game clock stops; Esc/back steps back (settings → menu → game). On resume the scene drains buffered attack, dodge and talk input. The menu has 계속하기, 설정 and, only on native (`Capacitor.isNativePlatform()`), 게임 종료. Settings (button size, joystick size, just-dodge timing) live in the pure `ui/settingsData.ts`, are saved under `untitled-rpg.settings` separately from progress, fall back per field to defaults when invalid, and are applied by `applySettings()` (`ActionButton.setSizeScale`, `VirtualJoystick.setSizeScale`, `justDodgeWindow`). There is deliberately no in-game 'start over' option. After adding a Capacitor plugin, run `npx cap sync android` and commit the regenerated `android/*.gradle` files.

**Tuning** lives in `src/config.ts` (speeds, combo stages, dodge, `JUST_DODGE`, enemy ranges, `PROGRESSION` for XP per kill, XP curve and per-level gains). The version shown on screen comes from `package.json` `version` through Vite's `define` (`__APP_VERSION__`).

## Android and CI

Capacitor wraps `dist/` (`capacitor.config.ts`, `android/`). The app is locked to fullscreen landscape with the screen kept on (`MainActivity.java`, `AndroidManifest.xml`). `.github/workflows/android-apk.yml` runs `npm test` and then builds a debug APK on every push to `main` or `claude/**`, uploaded as the run artifact `untitled-rpg-apk`. Actions are pinned to commit hashes. Signing uses the private key from the `ANDROID_KEYSTORE_*` secrets when they are set, and otherwise the public test key `android/app/debug.keystore`, which must not be used for APKs given to other people.
