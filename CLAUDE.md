# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

`AGENTS.md` holds the repository's style, testing and commit conventions; follow it. This file adds what you need to work safely in the code.

## Working with the user

- Never commit or push on your own. Always ask the user first, every time. `.claude/settings.json` enforces this with a PreToolUse hook (`.claude/hooks/confirm-git-commit-push.sh`) that forces a permission prompt for `git commit`, `git push` and GitHub MCP file writes.
- The user writes in Korean; reply in Korean. Code comments and README are mostly Korean too.

## Commands

```bash
npm ci                     # install
npm run dev                # Vite on :5173, reachable from a phone on the same network
npm run typecheck          # tsc, strict, no emit (there is no linter)
npm test                   # node --test tools/*.test.mjs — needs Node.js 24+
npm run test:browser       # real game in headless Chromium; set CHROMIUM_PATH if `chromium` is not on PATH
npm run build              # dist/
npm run build:single       # dist-single/index.html with all JS and images inlined
npm run android:apk        # build + cap sync + gradle assembleDebug (needs the Android SDK)
```

Run one test file, or one test by name:

```bash
node --test tools/blade.test.mjs
```

```bash
node --test --test-name-pattern='회피' tools/*.test.mjs
```

The Node tests import `.ts` sources directly through Node 24's type stripping. Modules they import (`config.ts`, `entities/heroFrames.ts`, `entities/movement.ts`, `entities/progression.ts`, `entities/saveData.ts`, `story/dialogues.ts`, `story/quests.ts`, `items/inventory.ts`, `world/interactables.ts`, `world/maps.ts`, `world/worldMap.ts`, `world/interiors.ts`, `world/npcs.ts`, `world/villageLayout.ts`, `world/obstacles.ts`, `combat/blade.ts`, `combat/justDodge.ts`, `combat/hitFeel.ts`, `ui/settingsData.ts`, `world/navGrid.ts`) must stay free of Phaser and of Vite-only imports such as `?inline`, or the tests stop loading. Put new pure logic in modules like these so it can be tested. A pure module that imports another one must spell the `.ts` extension (`'../config.ts'`) for Node; `allowImportingTsExtensions` in `tsconfig.json` lets TypeScript accept it.

`?debug` in the URL draws the walkable polygon and obstacles. In dev builds the `Phaser.Game` is exposed as `window.__game`, which the browser test and ad-hoc Playwright checks use.

## Architecture

**Title screen.** `scenes/TitleScene.ts` (`'title'`) is the first scene: a temporary background (`src/assets/title/background.webp`, a downscaled copy of the Rowen overview art), the title and two buttons. 설정 reuses `PauseMenu.openSettings()` (settings view only; 돌아가기 closes) and saves to the same settings key. 시작하기 fades the camera out over `TITLE_FADE_MS` and starts `'game'` with `{ fromTitle: true }`, which makes `GameScene.create()` fade in over the same time (the flag is cleared from the data after use). In dev builds a `?map=` URL skips the title (`main.ts`), which the browser tests rely on; the last browser test covers the title flow.

**One scene, one clock.** `scenes/GameScene.ts` runs a whole session. All gameplay timing uses the scene's own `now` (ms), advanced in `update()` by `min(delta, 50)`. Attack timing, combos, dodge, invulnerability, respawns and effects all compare against it. Do not use `this.time.delayedCall` or `Date.now()` for gameplay; they drift from the game clock when frames drop. Per-run state is reset in `resetState()` from `init()`, because class field initialisers run only once and the scene must survive `scene.restart()`.

**Frame-rate independent motion.** Lunges and dodges are not speed × dt. They move by the change in an integrated progress curve (`entities/movement.ts`), so the distance is identical at any frame rate. Tests assert this at 20/30/60/120 fps. Keep new displacements in that form.

**Characters.** `entities/Character.ts` is a container whose position is the feet and whose depth is its y (y-sorting). Its body is either a Phaser `Sprite` (the slimes, from code-drawn textures in `world/placeholderArt.ts`) or a `HeroSprite` (the player). Both are driven by animation keys named `${key}-idle`, `${key}-walk`, `${key}-attack1..3` and `${key}-dodge`.

**The hero.** `entities/HeroSprite.ts` shows whole-character frames from `src/assets/hero/academy/*.png`. `entities/heroFrames.ts` is the pure part: it picks one of 8 facings from actual displacement (with hysteresis), maps attacks to the 6 non-vertical attack facings, and decides which frame is shown at each ms of an action. `HeroSprite.advance(ms)` is called by the scene with the game step (not real time), so its frames slow down, stop for hit stop and freeze while paused in step with the hit timing; driving it on real time makes attacks started during slow motion finish before their hit window and miss. Frame rectangles plus foot and blade anchors live in `frames.json`, generated by `tools/build_hero_frames.py` (`ANCHORS`, `DIAGONAL_ATTACK_ANCHORS`). The source sheets are never edited.

**Hits come from the drawn blade.** `HeroSprite.getBlade()` returns the guard and tip in world space for the current frame. `GameScene.updateAttackTrace` sweeps the blade between frames and tests it against each enemy with `combat/blade.ts` (`bladeHitsEllipse`, `clipBladeSweep`), inside a ground-plane lane from `insideAttackLane`. The trail effect uses the same blade positions, so what you see is what hits. Because each attack has only four drawn poses, the moment the strike pose appears (`strikePoseStart()` in `heroFrames.ts`) `CombatEffects.slash()` fills the jump from the previous pose's blade to the strike pose's blade with a tapered crescent (tip rotating around the guard, through the front side; a light streak for the thrust), which grows in `SLASH_GROW_MS`, holds and fades on the game clock in the same pooled Graphics; it is visual only. Three timings must agree: each combo stage's `hitDelayMs`/`intervalMs` in `config.ts`, the pose start times in `heroFrames.ts` (`POSE_STARTS`, `ACTION_DURATION`), and the drawn strike frame. `tools/hero-sprite.test.mjs` checks that.

**World and maps.** `world/maps.ts` (pure) lists the maps: the village in two maps joined by a centre road (`VILLAGE_LINK`) — 로웬 마을 북쪽 (`village-north`, the houses: Sion's, the chief's, the clinic and Linea's; `START_MAP`, spawn at Sion's door) and the square 로웬 마을 (`village`, training hall, shops, inn, south gate and the exits to the hunting grounds), neither with enemies — and the hunting grounds `south-field`, `west-forest`, `east-stream`, each with bounds, props, enemy spawns, interactables and exits. An exit is a zone at the walkable edge plus the arrival point in the target map; `tools/maps.test.mjs` checks that every exit has a way back, arrivals are walkable and outside exit zones, and spawns, exits and enemies are reachable. When the player's feet enter an exit zone, `GameScene.travel()` sets `traveling` (which makes `update()` return early), fades the camera out and calls `scene.restart({ map, at, hp })`. `init(data)` picks the map from that data, then `?map=` in dev builds, then the current map, so a plain `restart()` stays on the same map; the carried `hp` is cleared from the data after use. Level and XP need no carrying because they are saved. `world/village.ts` `buildMap()` draws any map: the shared ground texture (tinted per map), props, the map's buildings (each Rowen building has an `area` naming its village map, `buildingsIn(area)`; Linea's cottage comes from `linea-house.png`, with their names above the roof), the code-drawn stream and the exit labels. The hunting grounds reuse the village ground and props until they get their own art. `villageLayout.ts` holds the Rowen village layout (`BUILDINGS` with area, wall footprints and doors, `PROPS` for the square and `NORTH_PROPS`, `areaObstacles(area)`, the south gate passage); village art and measured frames live in `src/assets/village/`. The game loads small WebP copies made by `tools/build_rowen_assets.py` (buildings sheet, per-character `dialogue-768` and `walk_*-60`), never the multi-MB source PNGs; rerun it when the source art changes. The browser test loads the south field by default (`load(map)`), and a village map only for village tests. NPCs outside have an optional `area` (default the square); `regionOf` maps `village-north` to the village region on the world map. `WalkArea` uses rectangular building walls and ellipse obstacles for trunks/rocks, and divides movement into short steps to prevent dodge tunnelling. Draw depth follows the ground contact Y. Building walls come from `body()` in `villageLayout.ts`: they reach `FRONT` px below the art's bottom and `SIDE` px past its sides, so a character approaching from the front or side is always drawn in front of the art (feet below the art's bottom); the north map's top-row buildings' walls reach `WALK_BOUNDS.top` so there is no hidden pocket behind them; Characters behind other buildings or tree canopies are simply hidden by the art (no silhouette, by the user's choice). `world/navGrid.ts` is one shared flow field toward the player; it is recomputed only when the player changes cell, and enemies use it only when the straight line is blocked.

**Building interiors.** `world/interiors.ts` (pure, `tools/interiors.test.mjs`) lists one room per Rowen building except the south gate: size, floor and wall colours, and furniture placed in room coordinates (`(x, y)` is the front-centre on the floor, occupying `w × d`; rugs are walkable). Furniture and floors are measured on the interior artwork in `INTERIOR_ART` (pixel coordinates; `walk` is the floor polygon, narrower at the back like the art, so the back corners' windows and walls are not walkable; `shop` places a shopkeeper, e.g. Merina just behind the counter so it hides her legs). `maps.ts` turns each into a map `in-<id>` (bounds = room centred on `ROOM_CENTER`, `walkPolygon` from `interiorWalkPolygon()`, furniture obstacles, no walk-out exits) with one `exit-<id>` interactable at the door whose `enter` leads back to the building's `door`, and adds a door interactable per building to the village with `enter: { to, at, label }`. Near a village door the talk button reads 들어가기 and the marker shows the building name; inside, near the door it reads 나가기 (marker ▼ 나가기), so walking past the door never leaves; pressing it calls `travel()` like an exit. Shopkeepers may stand inside furniture (behind a counter); only their talk spot must be walkable. `world/interiorArt.ts` draws the room in code (planks, back wall with windows, side walls, a front sill drawn in front of characters with the door gap, furniture y-sorted by its front edge); replace it when interior art exists. `setCameraBounds()` limits the camera to the room and widens the bounds to the viewport when the room is smaller, so it stays centred; the minimap draws the floor and furniture for interiors.

**Village people.** `world/npcs.ts` (pure) lists the eleven NPCs (name, spot, height, dialogue id, `shop`, `wander` radius) and the wander rules (`pickWanderTarget`, `direction8`); `tools/npcs.test.mjs` checks it. `entities/Npc.ts` draws one from its 8-direction walk sheets (`walk_frames.json` × 0.6, found with `import.meta.glob`). Shopkeepers (Doran, Merina, Rosetta) stand inside their shops (`inside: InteriorId`, placed with `inRoom()`), have no `wander` and never walk, but turn to face the player; `talkOffset` moves their talk spot in front of the counter. The healer Eila lives inside the clinic during the day (`inside: 'clinic'`, a small `wander`, not a shop); `chapterNpcs()` moves her to the square during the raid and beside Linea's house in the north map afterwards, and after her normal lines in the clinic a `StoryChoice` offers the same heal as the clinic bed. Door markers ask `chapterNpcs()` who is inside now. Each map's `npcs` is filtered by `inside`. In the village, `doorMarkers` show the best quest marker of the people inside above a shop door (and on the minimap). Everyone else wanders. A walker idles, picks a reachable point within its radius, walks there on the game clock, and stops to face the player within `NPC_NOTICE_RADIUS` so it can be talked to. Walk frames advance by distance walked (`walkPose`, `NPC_STEP_RATIO` of the height per step), not by time, so feet do not slide; the hero's walk animation speed is likewise scaled by actual speed over `HERO_WALK_NATURAL_SPEED`. Each NPC owns an `Interactable` (`spot`) that follows it; the scene merges those with the map's interactables in `this.interactables`. NPCs do not collide with the player. Portraits for each NPC are registered in `DialogueBox.ts` under the NPC id, and each NPC's lines use its name as the speaker. A stress mode (pause menu button cycling `STRESS_STEPS` 0/50/100/200, or `?stress=N`) adds `stressNpcs()` copies that reuse the eleven walk sheets and shows `ui/PerfOverlay.ts` (FPS, longest frame, NPC count, texture-memory estimate, JS heap); `stressCount` is a scene field that survives restarts, and choosing a step restarts in the village.

**Quests and minimap.** `story/quests.ts` (pure, tested by `tools/quests.test.mjs`) defines the quests (giver NPC, optional prerequisite, one objective counting a `QuestEvent`: kill in a map or anywhere, combo finisher, or talking to an NPC), the state machine (`talkTo`, `recordEvent`, `markerFor` → `new`/`ready` for main quests (yellow), `sub-new`/`sub-ready` for side quests (green), `progress`/`target`; `MARKER_PRIORITY` orders them when several apply, e.g. on a shop door) and the save format under `untitled-rpg.quests` (separate from progress, invalid entries dropped per quest). The scene keeps `quests`, asks `talkTo()` first when the player talks to an NPC (falling back to the NPC's normal lines), fires `questEvent()` on kills and when a third combo stage starts, and calls `refreshQuests()` to update the head markers (`Npc.setQuestMarker`, styles in `MARKER_STYLE`) and `ui/QuestTracker.ts`. Rewards are XP plus optional `rewardGold`/`rewardItems`. `ui/Minimap.ts` draws a player-centred circular map into a canvas texture every 100 ms of real time (ground, props and buildings from the same atlases, exits, NPC and enemy dots, quest markers clamped to the rim when out of view); the scene passes a collector that is only called on redraw. Both are scene fields cleared in `resetState()` and rebuilt in `create()`. Tapping the minimap (or M) opens `ui/WorldMap.ts`, a full-map overlay built from the pure `world/worldMap.ts` (`REGIONS` on a grid, `ROUTES`, `regionOf` maps interiors to the village, visited regions saved under `untitled-rpg.visited`; `tools/world-map.test.mjs` checks routes match real exits). Unvisited regions and regions without a map show '?'; the world map shows no quest markers; while it is open `update()` returns early like the item panel.

**Gold and items.** `items/inventory.ts` (pure, `tools/inventory.test.mjs`) defines the items (`ITEMS`: potion and lunch heal, slime gel is a sellable material), the immutable `Inventory` operations (`addItem`, `useItem`, `bestHealItem`, `buy`, `sell`, `slimeDrop`/`applyDrop`) and the save under `untitled-rpg.inventory`. The scene keeps `inventory`; a kill calls `collectDrop()` (gold and items are picked up at once, shown with `ProgressEffects.showPopup`), quest completion calls `giveRewards()`, the potion button above the dodge button (key Q) uses the best-fitting heal item with `USE_COOLDOWN_MS` on the game clock, and `ui/ItemPanel.ts` is the bag (from the pause menu) and Merina's shop (opened after her normal dialogue). While the panel is open `update()` returns early like the pause menu, and closing it drains input through `onResume()`.

**Rest points (save where you rested).** `story/restPoints.ts` (pure, `tools/rest-points.test.mjs`) defines the two places to rest: the inn (after Rosetta's normal lines a `StoryChoice` asks 쉬어 가기) and Sion's bed (`HOME_BED_SPOT`, an interactable added in `in-home` whose button reads 쉬기). Resting fills HP and saves the place under `untitled-rpg.rest`; level, quests and items are saved as they change anyway, so only the restart position is stored. `GameScene.init()` uses it only when the scene starts from the title (`fromTitle` without a map); no rest yet means Sion's door. `canRest()` blocks resting during the raid. Death still revives on the current map. The clinic has a third bed spot, `CLINIC_BED_SPOT` (`heal-clinic`, button 치료받기, added in `in-clinic`): it fills HP and clears the dusk-moth slow (`slowedUntil`) but saves nothing, and works during the raid too. It also grants 약초 기운: max HP + `herbBonus()` (`HERB_BONUS_RATIO` of the base, the scene's `herb` field), filled at once and shown green on the HUD bar. It has no timer; it lasts until the player is first hit (`onEnemyStrike` drops it and clamps HP to the base max), is carried across maps in the restart data (`herb`), does not stack, and is lost on relaunch.

**Mana and 회전 베기.** The pure `combat/mana.ts` (`tools/mana.test.mjs`) holds `maxManaForLevel`, `regenMana`, `addMana` and `inSpinRadius`; tuning is `MANA` and `SPIN_SLASH` in `config.ts`. The scene keeps `mp` (a float; the HUD MP bar between HP and XP shows the floor and is redrawn only when that changes, `drawMp`) and `maxMp`. Mana regenerates on the game clock, rises by `MANA.perHit` per sword hit, fills on level-up, rests and clinic heals, starts full and is carried across maps in the restart data (`mp`). The skill button above the potion button (key K) calls `startSpin()` when not attacking or dodging and off cooldown: it spends `SPIN_SLASH.cost`, plays the third combo pose in place and sets `spinHitAt`; `spinHit()` then hits every living enemy inside the ground ellipse once. Hit aftermath (kill, XP, quest event, drop, or knockback) is shared with the sword in `resolveEnemyHit()`.

**Dusk moths.** From the moment the main quest 해 질 무렵의 순찰 is accepted until 축제 전야 is done (`isDusk()` in `story/chapterOne.ts`), the south field adds four 잿빛 나방 (`ashen-moth`, `DUSK_MOTH_POINTS` through `fieldPoint`) via `GameScene.duskSpawns()`, and its entry hint changes. The moth has walk sheets only (`MonsterSprite` falls back to the walk frame of the same pose for attacks) and hovers 28 px above its shadow; its hit slows the player to `ASH_SLOW.speedScale` for `ASH_SLOW.durationMs` on the game clock (`slowedUntil`).

**Enemies.** `combat/Enemy.ts` is a small state machine: wander → chase → windup (telegraph) → strike → recover, timed on the game clock. When the strike lands it records `lastStrikeAt` and calls back into the scene, which decides whether the player is hit (`strikeReaches` in `combat/justDodge.ts`).

**Just dodge.** A dodge started within `JUST_DODGE.windowMs` before a strike lands, from a spot the strike would have reached, is a just dodge (`isJustDodge`, checked against the dodge's start position, once per dodge). It slows the game clock: `update()` multiplies the frame step by `slowMotionScale(...)` for `slowMs` of real time, so enemies, the player and all game timers slow together. It also resets the dodge cooldown, stuns the dodged enemy for `stunMs`, and marks the next attack started within `counterMs` as a counter (`attackTrace.counter`, damage × `counterDamage`).

**Hit stop and hit reaction.** A sword hit, a finisher, a counter and the player getting hurt each set `hitStopLeft` (`HIT_FEEL.*HitStopMs`, real-time ms, longest wins). `update()` computes the step scale with `gameTimeScale(hitStopLeft, slowMotionLeft)` from `combat/hitFeel.ts`; while it is 0 the frame returns early, and pending button/key presses stay queued for the next frame. A hit slime calls `Enemy.onHit(now)`, which flattens it and lets it bounce back on the game clock (`hitSquash`).

**Heavy hits.** Each blade contact is classified by the pure `strikeKind()` in `combat/hitFeel.ts` (counter > finisher > crit > normal; `HIT_FEEL.critChance`/`critDamage`, no crits on counters); the heaviest kind of the swing picks the hit stop, the camera shake (`HIT_FEEL.shake`) and a brief screen tint. `combat/ImpactEffects.ts` draws the contact flash and sparks, a ground shock ring and dust for heavy hits, slide dust under strongly knocked-back characters, dodge dust, and a splatter when a slime dies. Its 120 particle images are created up front and recycled, move on the game clock (so they freeze during hit stop and slow with just-dodge slow motion), and only the screen tint fades in real time.

**No per-hit allocation.** Damage numbers (`ui/DamageNumbers.ts`, digits drawn once to a texture), blade trails and dodge ghosts (`combat/CombatEffects.ts`) reuse pooled objects. Keep new combat effects pooled; the target is low-end Android.

**Progression.** The scene keeps `progress` (level, xp) and `stats` (max HP and damage for that level) and resets both in `resetState()`. Killing an enemy calls `gainXp()`, which uses the pure `entities/progression.ts` (`addXp`, `statsForLevel`, `xpToNext`); a level-up raises max HP, heals fully, and updates the name label, the HUD XP bar and the pooled effects in `ui/ProgressEffects.ts`. Player damage reads `stats`, not `PLAYER.damageMin/Max` directly. Progress survives death and is saved to `localStorage` (key `untitled-rpg.save`, versioned) on every XP change by `entities/saveData.ts`; `init()` loads it, so restarts and app relaunches continue from it. The storage is passed in, so a blocked or full `localStorage` only disables saving, and a corrupt or out-of-range save is ignored (new game). Bump `SAVE_VERSION` when the saved shape changes. Uninstalling the app clears the save.

**Dialogue.** `world/interactables.ts` lists talkable spots (ground position, reach radius, marker height, dialogue id); `story/dialogues.ts` holds the lines (speaker, text, optional portrait), currently placeholder text until the story is written. When the player stands near a spot and no enemy is chasing or attacking, the scene shows a marker and a 대화 button (keys E/Enter). `ui/DialogueBox.ts` types lines out and advances on any tap, E/Enter or Space/J. While it is open `update()` returns before advancing `now`, so the whole game is frozen; on close the scene clears buffered attack and dodge input so the advancing key does not attack. Portraits are runtime copies (e.g. `assets/hero/dialogue/neutral-768.png`); add new ones to `PORTRAITS` in `DialogueBox.ts` and the `Portrait` type. New NPCs need an entry in `world/npcs.ts`, a dialogue entry, a portrait and their walk sheets plus `walk_frames.json` (`tools/build_npc_frames.py`), with runtime copies made by `tools/build_rowen_assets.py`.

**Pause and settings.** The top-right II button, Esc, the Android back button (`@capacitor/app` `backButton` listener; without it Android would close the app) and the game going hidden all open `ui/PauseMenu.ts`. While it is open `update()` returns before anything else, so the game clock stops; Esc/back steps back (settings → menu → game). On resume the scene drains buffered attack, dodge and talk input. The menu has 계속하기, 설정 and, only on native (`Capacitor.isNativePlatform()`), 게임 종료. 게임 종료 destroys the Phaser game before `App.exitApp()`, and `MainActivity.onDestroy()` destroys the WebView and kills the process when the activity is finishing: `exitApp` only calls `finish()` and Capacitor does not destroy the WebView, so the old game lingered in the process and the next launch stuttered. Settings (button size, joystick size, just-dodge timing) live in the pure `ui/settingsData.ts`, are saved under `untitled-rpg.settings` separately from progress, fall back per field to defaults when invalid, and are applied by `applySettings()` (`ActionButton.setSizeScale`, `VirtualJoystick.setSizeScale`, `justDodgeWindow`). There is deliberately no in-game 'start over' option. After adding a Capacitor plugin, run `npx cap sync android` and commit the regenerated `android/*.gradle` files.

**Tuning** lives in `src/config.ts` (speeds, combo stages, dodge, `JUST_DODGE`, `HIT_FEEL`, enemy ranges, `PROGRESSION` for XP per kill, XP curve and per-level gains). The version shown on screen comes from `package.json` `version` through Vite's `define` (`__APP_VERSION__`).

## Android and CI

Capacitor wraps `dist/` (`capacitor.config.ts`, `android/`). The app is locked to fullscreen landscape with the screen kept on (`MainActivity.java`, `AndroidManifest.xml`). `.github/workflows/android-apk.yml` runs `npm test` and then builds a debug APK on every push to `main` or `claude/**`, uploaded as the run artifact `untitled-rpg-apk`. `setup-java` caches Gradle downloads (`cache: gradle`), because fetching every dependency from Maven Central on each run sometimes failed with 429 Too Many Requests. Actions are pinned to commit hashes. Signing uses the private key from the `ANDROID_KEYSTORE_*` secrets when they are set, and otherwise the public test key `android/app/debug.keystore`, which must not be used for APKs given to other people.
