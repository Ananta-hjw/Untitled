# Untitled

모바일 RPG 프로토타입. Phaser + TypeScript + Vite.

처음 화면(시작하기·설정)에서 시작하기를 누르면 화면이 스르르 바뀌며 시온의 집 앞(여관의 로제타나 집 침대에서 쉬었다면 그곳)에서 시작해 아홉 채의 건물과 마을 사람 열한 명이 있는 로웬 마을을 가상 조이스틱으로 돌아다니며 말을 걸고,
새 게임을 처음 시작하면 조작하기 전에 수확제 전날 아침 시온이 마을 사람들(세레나, 헤르만, 시아, 리네아)을 만나는 짧은 이야기(약 2분)가 한 번 나온다. 오른쪽 위 건너뛰기(또는 Esc·뒤로 가기)로 넘길 수 있다.
마을 밖 사냥터(남쪽 들판, 서쪽 숲길, 동쪽 개울가)에서 공격 버튼(누르고 있으면 3단 콤보)과 회피 버튼으로 몬스터와 실시간으로 싸운다.
주인공은 천무학관 기반의 상하좌우·대각선 8방향 대기·걷기 시트와 같은 디자인의 좌우·대각선 3단 공격 및 회피 시트를 사용한다. 나머지는 코드로 그린 임시 그래픽이다.

루안의 수련을 마치면 보고·축제 준비·매듭·수확제 일손·순찰·잿빛 나방 쫓기·잔치·마을 방어(입구 → 여관 앞 → 북쪽 길의 세 무리)·동생 수색·서신 확인·도란의 첫 진짜 검까지 메인 퀘스트가 자동으로 이어진다. 사냥터마다 권장 레벨이 있고(남쪽 들판 1~3, 서쪽 숲길 4~6, 동쪽 개울가 7~9) 몬스터 머리 위에 레벨이 보인다. 몬스터보다 3레벨 이상 높으면 경험치가 줄어든다. 축제 시작 전에는 탐색을 계속할 수 있고, 진행 단계와 습격에서 남은 적 수는 저장된다. 자세한 흐름은 [1장](docs/story-chapter1.md)을 참고한다.

## 실행

```bash
npm install
```

```bash
npm run dev
```

같은 와이파이의 휴대폰에서 터미널에 표시되는 Network 주소로 접속하면 터치로 조작할 수 있다.
PC에서는 방향키나 WASD로 움직이고 스페이스바나 J로 공격, Shift나 K로 회피한다. 적의 돌진이 닿기 직전에 회피하면 저스트 회피가 되어 잠깐 느려지고 다음 공격이 강해진다. 말을 걸 수 있는 곳 근처에서는 E나 Enter로 대화한다. 오른쪽 위 II 버튼이나 Esc(안드로이드는 뒤로가기)로 일시정지하고, 설정에서 버튼·조이스틱 크기와 저스트 회피 판정을 바꿀 수 있다. 설정은 세 가지 옵션을 직접 눌러 선택하며, 선택 표시·크기 미리보기·회피 판정 설명이 즉시 바뀐다. 기본값 복원으로 세 항목을 한 번에 되돌릴 수 있고 변경은 기기에 바로 저장된다. 첫 화면은 높은 곳에서 에르다인을 바라보는 시온의 뒷모습을 배경으로 사용한다. 주소 뒤에 `?debug`를 붙이면 이동 가능 영역이 보인다.

| 명령 | 설명 |
|---|---|
| `npm run dev` | 개발 서버 |
| `npm run build` | 배포용 빌드 (`dist/`) |
| `npm run build:single` | HTML 한 파일로 묶은 빌드 (`dist-single/`) |
| `npm run typecheck` | 타입 검사 |

## 회귀 검사

```bash
node --test tools/*.test.mjs
npm run test:browser
```

브라우저 검사는 Chromium이 필요하며, 개발 서버와 임시 브라우저를 자동으로 실행하고 종료한다.
실행 파일 경로가 기본값과 다르면 `CHROMIUM_PATH`로 지정한다.
장면 재시작, 공통 게임 시계, 부활, 가변 프레임 회피 거리, 짧은 공격 입력, 타격 시간 경계와 효과 객체 재사용을 실제 게임 코드로 검사한다.

## 로웬 마을

마을은 2400×1600 맵 두 개로 나뉘고, 가운데 길로 오간다(`docs/rowen-village.md`).
- **로웬 마을 북쪽** (집들이 있는 곳, `village-north`): 시온의 집, 촌장의 집, 치유소가 위쪽에 줄지어 있고, 아래쪽 꽃밭 옆에 리네아의 집이 있다. 새 게임은 시온의 집 앞에서 시작한다. 아래쪽 가운데 길로 광장에 간다.
- **로웬 마을 광장** (`village`): 가운데 큰 나무를 두고 서쪽 수련소, 동쪽 잡화점, 남서쪽 대장간, 남동쪽 여관, 남쪽 입구(초소·아치·행상 수레)가 둘러싼다. 위쪽 가운데 길로 마을 북쪽에, 서·동·남쪽 출구로 사냥터에 간다.

건물 이름은 지붕 위에 띄운다.
건물은 그림 아래 끝보다 조금 앞, 그림 양옆보다 조금 바깥까지 땅을 차지하는 영역 전체를 사각형으로 막아(앞이나 옆에서 다가가도 건물 그림에 몸이 가려지지 않는다), 캐릭터가 벽을 뚫고 지나가지 못한다(마을 북쪽 위쪽 줄 건물은 뒤쪽 끝까지 막혀 있다. 다른 건물이나 큰 나무 뒤로 돌아가면 캐릭터는 그림에 가려진다). 건물마다 문 앞 위치(`door`)를 정해 두었고, 나중에 건물 안으로 들어가는 입구로 쓴다. 나무줄기와 바위는 타원으로 막으며, 지붕·나뭇잎과의 겹침은 발 위치로 정렬한다.
남쪽 입구는 아치의 두 기둥 사이로만 지나간다. 마을은 평화로운 곳이라 몬스터가 나오지 않는다.

**마을 사람.** 열한 명이 머리 위에 이름을 달고 서 있고, 다가가면 대화할 수 있다(대화창에 그 사람의 이름과 그림이 나온다).
모두 8방향 걷기 그림으로 그린다. 장사하는 사람은 가게 안에 있다: 메리나는 잡화점 카운터 뒤, 도란은 대장간 모루 옆, 로제타는 여관 바 뒤(이름표가 금색). 카운터 앞에서 말을 걸 수 있고, 걷지 않으며 시온이 오면 돌아본다. 마을에서는 안에 있는 사람에게 퀘스트가 있으면 가게 문 위와 미니맵에 표시가 뜬다.
걸음 그림은 시간이 아니라 실제로 걸은 거리에 맞춰 넘어가서(한 걸음 = 키의 약 0.29배) 발이 바닥에서 미끄러지지 않는다. 시온도 실제 이동 속도에 맞춰 걸음 그림을 넘긴다.
나머지 여덟 명은 자기 자리 주변을 천천히 돌아다니다가 시온이 가까이 오면 멈춰서 바라본다. 세레나, 시아, 리네아, 헤르만은 마을 북쪽에, 루안, 베르넬, 테온은 광장에 있고, 치유사 에일라는 치유소 안에서 지내며 말을 걸면 치료해 준다(습격 뒤에는 리네아 곁에 있다).
페른은 습격 다음 날 도착하므로 첫날에는 없다.

배치는 `src/world/villageLayout.ts`와 `src/world/npcs.ts`, 그림은 `src/assets/village/`와 `src/assets/characters/`에서 관리한다.
원본 그림은 크기가 커서, 게임에는 `python3 tools/build_rowen_assets.py`로 만든 작은 WebP 사본
(`rowen/buildings.webp`, 인물별 `dialogue-768.webp`, `walk_*-60.webp`)을 쓴다. 원본을 바꾸면 이 스크립트를 다시 실행한다.
나무·바위 소품은 `python3 tools/build_village_frames.py`로 프레임을 측정한다.
`?debug`를 붙이면 사각형 벽·타원 장애물, 이동 경계, 출구 영역(노란 사각형)을 확인할 수 있다.

## 퀘스트와 미니맵

마을 사람 머리 위에 퀘스트 표시가 뜬다. **!**는 새 퀘스트, **?**는 완료(보고)이고, 메인 퀘스트(루안의 수련)는 노란색, 서브 퀘스트는 초록색이다. 회색 **?**는 진행 중,
하늘색 **!**는 심부름으로 말을 걸어야 할 사람이다. 말을 걸면 퀘스트를 받고, 목표를 채운 뒤 다시 말을 걸면 완료하고 경험치를 받는다.
진행 중인 퀘스트는 미니맵 아래에 "제목 · 목표 3/5"로 보이고, 퀘스트 진행은 기기에 따로 저장된다(`untitled-rpg.quests`).
지금 있는 퀘스트는 루안의 수련 세 단계(마무리 일격 3번 → 남쪽 들판 슬라임 5 → 서쪽 숲길 마물 5),
도란의 담금질 재료(어디서든 슬라임 5), 테온의 초소 도시락(로제타에게 받아 오기)이다. 보상은 경험치와 골드, 아이템이다(루안의 첫 수련은 회복 물약 3개, 테온은 도시락).
퀘스트는 `src/story/quests.ts`에서 관리한다.

오른쪽 위의 둥근 미니맵은 시온을 가운데 두고 주변의 지형, 건물, 나무, 출구(노란 화살표), 마을 사람(흰 점), 몬스터(빨간 점)를 보여 준다.
퀘스트 표시가 있는 사람이 미니맵 밖에 있으면 가장자리에 그 방향으로 표시가 붙는다. 0.1초마다 다시 그린다(`src/ui/Minimap.ts`).
버전 표시는 화면 아래 가운데로 옮겼다.

**현재 지역 지도**: 미니맵을 누르거나 M 키를 누르면 지금 들어와 있는 맵 전체가 실제 지형·건물 그림으로 표시됩니다. 파란 점은 내 위치, 흰 점은 마을 사람, 빨간 점은 몬스터이며 연결 통로에는 목적지가 보입니다. 실내에서도 해당 방의 원화를 보여 줍니다. 퀘스트 표시는 기존 미니맵·추적창에서 확인합니다.
지도는 열린 동안 게임을 멈추며 닫기 버튼·바깥 여백·Esc·M으로 닫습니다. 지도 그림을 누르는 것으로 닫히거나 다른 지역으로 이동하지 않습니다. 지형 미리보기는 1024픽셀 캔버스 하나를 미니맵과 공유하고 맵이 바뀔 때만 다시 만듭니다.
**출구 안내**: 실제 동서남북 통로의 240px 이내에 다가가면 방향과 연결 맵 이름이 나타나고, 멀어지면 사라집니다. 습격 중에는 이동 제한을 표시합니다. 가 본 지역의 기록은 기존 저장 형식을 유지합니다.

## 골드와 아이템

골드는 슬라임(3~6G)과 퀘스트 보상으로 얻고, HP·경험치 막대 아래에 표시된다. 슬라임은 가끔 **슬라임 점액**(재료)이나 **회복 물약**을 떨어뜨린다.
회피 버튼 위의 **슬롯 1(Q)·슬롯 2(R)**에는 원하는 소모품을 직접 등록한다. 처음에는 빈 슬롯이며, 눌러서 가진 소모품을 고른다. 등록한 버튼을 길게 누르거나 가방의 슬롯 설정에서 교체·해제할 수 있고 등록은 기기에 저장된다. 두 슬롯과 가방 사용은 **공용 20초 대기 시간**을 적용하며 원형 암부와 남은 초를 표시한다. 메뉴·대화 중에는 시간이 멈추고, 맵 이동·아이템 교체 후에도 대기는 이어진다.
일시정지 메뉴의 **가방**에서 가진 아이템을 보고 쓸 수 있다. 메리나에게 말을 걸면 대화 뒤에 잡화점이 열려 물약과 도시락을 사고, 가진 물건을 판다.
가방은 기기에 따로 저장된다(`untitled-rpg.inventory`). 아이템은 `src/items/inventory.ts`에서 관리한다.

### 막기

오른쪽 아래 모서리의 **막기** 버튼(키보드 L)은 패링이다. 누르는 순간부터 0.25초 동안만 앞에 방패 빛이 생기고, 그사이 바라보는 쪽에서 온 공격을 막으면 "패링!": 피해를 전혀 받지 않고, 공격한 적은 1.2초 휘청이며 다음 공격은 반격(추가 피해)이 된다. 패링에 성공하면 바로 다시 막을 수 있고, 헛막으면 1초 동안 막기 버튼을 쓸 수 없다. 뒤에서 오는 공격과 판정 시간이 지난 공격은 막지 못한다. 회피는 재사용 대기가 10초다(민첩으로 최대 30% 줄어든다).

### 캐릭터 창 (상태 · 장비 · 아이템)

오른쪽 위 일시정지 버튼 아래의 **정보** 버튼(키보드 C, 아이템 탭은 I)이나 일시정지 메뉴의 **가방**으로 연다. 열려 있는 동안 게임은 멈춘다.

- **상태**: 힘(STR)·체력(VIT)·방어력(DEF)·민첩(DEX)·지능(INT)·행운(LUK). 레벨이 오를 때마다 포인트 3을 받아 `+` 버튼으로 직접 올린다. 각 줄 아래에 포인트 하나로 무엇이 얼마나 바뀌는지 나오고, 오른쪽에 전투 능력이 나온다.
  - 힘: 공격력 / 체력: 최대 체력 / 방어력: 받는 피해 감소(최소 1) / 민첩: 공격을 피할 확률(포인트당 0.2%, 최대 30%)과 회피 재사용 대기 감소(포인트당 0.5%, 최대 30%) / 지능: 최대 마나, 스킬·마법 피해 / 행운: 치명타 확률, 골드
- **장비**: 무기·머리·몸·장갑·신발·장신구 2칸. 칸을 누르고 낄 장비를 고른다. 처음에는 나무검과 낡은 수련복을 입고 있다.
- **아이템**: 가방의 소모품·재료·장비를 아이콘으로 보고, 물약을 쓰거나 장비를 바로 낀다.
- **도란의 대장간**: 도란에게 말을 걸면 짧은 검(STR +2)·긴 검(STR +4)과 방어구·장신구를 사고판다. 철검(STR +6)은 팔지 않고, 습격 뒤 메인 퀘스트 "첫 진짜 검"에서 도란이 건넨다.

능력치 분배와 장비는 `untitled-rpg.character`에 따로 저장된다. 아이콘은 `src/assets/icons/`에 이름을 맞춰 넣으면 자동으로 쓰인다(`src/assets/icons/README.md`).

## 화면 갱신 횟수

발열과 전력을 줄이려고 플레이 중에는 1초에 60번, 일시정지·대화·가방 같은 창이 열려 게임이 멈춰 있을 때는 30번만 화면을 그린다(`src/core/frameRate.ts`). 120Hz 화면의 휴대폰도 60번만 그리며, 안드로이드 앱은 화면을 60Hz로 바꿔 달라고 요청한다.

## 성능 테스트 모드

일시정지 메뉴의 **성능 테스트** 버튼을 누를 때마다 끔 → 50명 → 100명 → 200명 → 끔으로 바뀌고, 마을에서 다시 시작한다.
기존 마을 사람 열한 명의 그림을 돌려 써서 그만큼의 사람을 마을 곳곳에 더 세우고 모두 돌아다니게 한다.
켜져 있는 동안 왼쪽 위에 FPS(평균·최저), 가장 긴 프레임, 인물 수, 그림 메모리 추정치(불러온 텍스처의 가로×세로×4바이트 합,
글자 제외), JS 메모리(지원하는 브라우저·WebView에서만)를 0.5초마다 보여 준다. 브라우저에서는 주소에 `?stress=100`을 붙여도 된다.
같은 그림을 여럿이 나눠 쓰는 경우를 재는 것이라, 서로 다른 인물 100명의 메모리는 인물 수에 비례해 더 늘어난다.

## 건물 안으로 들어가기

남쪽 입구를 뺀 여덟 건물(시온의 집, 리네아의 집, 촌장의 집, 치유소, 수련소, 잡화점, 대장간, 여관)에 실내가 있다.
건물 문 앞에 서면 머리 위에 "▲ 건물 이름"이 뜨고 대화 버튼이 **들어가기**로 바뀐다. 누르면 화면이 어두워지며 실내로 들어가고,
실내 문 앞에서 나가기 버튼을 누르면(문 근처를 지나가기만 해서는 나가지 않는다) 그 건물 문 앞에 선다. 바닥은 원화처럼 뒤로 갈수록 좁아지는 모양이라 뒤쪽 창문·벽 위로 올라서지 않는다. 실내에는 침대, 탁자, 선반, 카운터, 화덕, 모루, 허수아비 같은 가구가 있고 가구는 지나갈 수 없다(깔개는 밟을 수 있다).
실내 그림이 아직 없어서 바닥·벽·가구를 코드로 그린 임시 모습이다. 배치는 `src/world/interiors.ts`, 그리는 부분은 `src/world/interiorArt.ts`에 있어 그림이 생기면 그리는 부분만 바꾼다.
장사하는 세 사람(메리나, 도란, 로제타)은 가게 안에 있다. 개발 서버에서는 `?map=in-home`처럼 실내에서 바로 시작할 수 있다.

## 맵 이동

로웬 마을 광장의 남쪽 입구 아치, 서쪽·동쪽 가장자리에 출구가 있고, 위쪽 가운데 길은 마을 북쪽으로 이어진다. 출구 영역에 발이 들어가면 화면이 잠깐 어두워지며
남쪽 들판, 서쪽 숲길, 동쪽 개울가로 옮겨 가고, 각 사냥터의 출구로 마을에 돌아온다.
옮겨 가는 동안에는 게임이 멈추고, 체력은 그대로 이어지며 레벨·경험치는 저장된 그대로다.
사냥터는 아직 전용 그림이 없어서 마을의 지면과 소품을 다른 배치·색조로 다시 쓰고, 개울은 코드로 그린다.
몬스터는 지금은 슬라임뿐이다(스토리 문서의 새 몬스터는 그림이 생기면 추가한다).

맵과 출구는 `src/world/maps.ts`에서 관리한다. 개발 서버에서는 주소에 `?map=south-field`처럼 붙여
그 맵에서 바로 시작할 수 있다 (`village`, `village-north`, `south-field`, `west-forest`, `east-stream`).

## 주인공 그림을 고쳤을 때

현재 캐릭터는 `src/assets/hero/academy/`의 `player_walk.png`, `player_walk_diagonal.png`, `player_combat.png`, `player_attack_down.png`, `player_attack_up.png`를 사용한다.
원본 시트를 편집하지 않고 프레임 영역과 발·검날 기준점을 별도 JSON으로 관리한다. 공격은 이동 입력을 우선하고, 입력이 없으면 근처 적 또는 마지막 방향을 사용한다. 한 타격 동안 방향을 고정하며 전진·넉백·검날 판정이 같은 방향을 따른다.
공격 그림을 교체할 때는 `tools/build_hero_frames.py`의 `ANCHORS`와 파츠 영역도 다시 측정한다.

```bash
python3 tools/build_hero_frames.py
npm run build
node --test tools/*.test.mjs
npm run test:browser
```

`heroFrames.ts`의 공격 프레임 시점은 `src/config.ts`의 콤보 명중 구간과 함께 조정한다.
게임 화면에서 여덟 방향 이동·정지, 좌우·대각선 4방향의 3단 공격, 회피, 발 높이와 이름표를 확인한다.

## 안드로이드 APK

Capacitor로 웹 빌드를 안드로이드 앱으로 감싼다 (`android/`, `capacitor.config.ts`).
푸시하면 GitHub Actions(`.github/workflows/android-apk.yml`)가 테스트용 APK를 만든다.
저장소의 Actions 탭 → 해당 실행 → Artifacts의 `untitled-rpg-apk`에서 받을 수 있다 (GitHub 로그인 필요, zip으로 내려온다).

안드로이드 스튜디오가 설치된 PC에서 직접 만들 때:

```bash
npm run build
```

```bash
npx cap sync android
```

```bash
cd android && ./gradlew assembleDebug
```

결과물은 `android/app/build/outputs/apk/debug/app-debug.apk`.
화면에 표시되는 버전은 `package.json`의 `version`을 따른다.

### 서명 키

기본값은 저장소에 들어 있는 테스트용 키(`android/app/debug.keystore`)다. 이 키는 공개되어 있어서
누구나 같은 서명의 APK를 만들 수 있다. 본인 기기 테스트에만 쓰고, 다른 사람에게 나눠 주기 전에
비공개 키로 바꾼다.

1. 키를 만든다 (비밀번호와 별칭은 직접 정한다. 이 파일은 저장소에 올리지 않는다).

```bash
keytool -genkeypair -keystore signing.keystore -alias untitled -keyalg RSA -keysize 2048 -validity 10000
```

2. 키 파일을 한 줄 문자열로 바꾼다.

```bash
base64 -w 0 signing.keystore
```

3. 저장소 Settings → Secrets and variables → Actions 에 다음 네 개를 등록한다.

| 이름 | 값 |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | 2번에서 나온 문자열 |
| `ANDROID_KEYSTORE_PASSWORD` | 키 저장소 비밀번호 |
| `ANDROID_KEY_ALIAS` | 별칭 (위 예시에서는 `untitled`) |
| `ANDROID_KEY_PASSWORD` | 키 비밀번호 |

등록한 뒤의 빌드부터 비공개 키로 서명된다. 서명이 바뀌므로 기존에 설치한 앱은 한 번 지우고 다시 설치해야 한다.
그다음 `android/app/debug.keystore`와 `build.gradle`의 테스트용 키 부분을 지우면 된다.
스토어 출시에는 이와 별도로 릴리스 빌드 설정과 고유한 앱 ID가 필요하다.

잡화점은 구매·판매 탭으로 나뉘며 한 번에 1개씩 거래한다. 물품 효과·보유 수량·가격과 거래 결과를 창 안에서 확인할 수 있다. 골드 부족·보유 한도에서는 거래가 비활성화된다. 여관의 휴식 확인 창은 현재/최대 체력과 다음 시작 위치를 먼저 보여 주며, 무료로 쉬어도 퀘스트나 시간대는 진행되지 않는다.

로웬 마을의 일반 병사는 세 문에 2명씩, 광장·주거지 순찰에 4명으로 총 10명이다. 문지기는 제자리를 지키고 순찰병은 걸어 다니며, 말을 걸면 안내한다. 병사들의 대화·SD·8방향 이동 원화와 런타임 압축본은 `src/assets/characters/soldier/`에 있으며 모든 병사가 같은 그래픽을 공유한다.
